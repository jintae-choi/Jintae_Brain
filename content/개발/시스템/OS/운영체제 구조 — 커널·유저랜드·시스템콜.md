## 개요
> 운영체제(OS)를 **커널 + 유저랜드** 두 층으로 쪼개 보면, 리눅스 배포판 차이·컨테이너가 가벼운 이유·Windows의 WSL2 구조가 한 번에 풀린다. 컨테이너 쪽 상세는 [[2. Docker 핵심 개념]], [[5. 컨테이너 생명주기]].

---

## 1. 전체 개념 / 흐름

### 1-1. 큰 그림 — OS는 두 층이다

"운영체제(OS)"는 한 덩어리가 아니라 두 부분으로 나뉜다. 이걸 안 나누면 계속 헷갈린다.

```
운영체제(OS) = 커널(kernel)  +  유저랜드(userland)
                ────────────      ─────────────────
                하드웨어 관리자      그 위에서 도는 나머지 전부
```

프로그램이 하드웨어를 쓰는 경로:

```
[내 프로그램] ──시스템콜(open, read…)──► [커널] ──► [하드웨어]
   유저 모드          = OS API              커널 모드     CPU·메모리·디스크·네트워크
```

### 1-2. 사전 지식 / 용어

- **커널(kernel)** — OS의 핵심. CPU·메모리·디스크·네트워크 같은 **하드웨어를 직접 관리**하고 프로세스에 자원을 나눠준다. 특권(커널) 모드에서 돈다.
- **유저랜드(userland)** — 커널 위에서 도는 전부: 셸(`bash`), 라이브러리(`glibc`), 명령어(`ls`·`cat`), 배포판 파일들(`/bin`·`/etc`). 우리가 "우분투"라 부르는 것의 대부분이 여기.
- **시스템 콜(system call) = OS API** — 유저 프로그램이 커널에 일을 부탁하는 **창구**. `open`(파일 열기)·`mmap`(메모리)·`send`(네트워크) 등. 프로그램은 하드웨어를 직접 못 만지니 **반드시 시스템콜로 커널에 요청**한다.
- **유저 모드 / 커널 모드** — CPU의 권한 단계. 유저 모드 프로그램은 하드웨어에 직접 접근 못 하고, 시스템콜을 부를 때만 잠깐 커널 모드로 넘어간다.

### 1-3. 비교 — 리눅스 배포판 차이는 "유저랜드" 차이

우분투·데비안·알파인은 서로 다른 배포판이지만, **전부 같은 리눅스 커널을 공유**한다. 다른 건 유저랜드뿐.

```
우분투 / 데비안 / 알파인   ← 유저랜드는 서로 다름(패키지 관리자·파일 배치·기본 라이브러리)
        └────────┬────────┘
            같은 리눅스 커널   ← 이건 공유
```

| 항목 | 우분투 | 알파인 | 공유? |
|---|---|---|---|
| 커널 | 리눅스 | 리눅스 | 공유(같음) |
| 패키지 관리자 | `apt` | `apk` | 다름(유저랜드) |
| 기본 libc | glibc | musl | 다름(유저랜드) |
| 이미지 크기 | 큼 | 작음(수 MB) | — |

> 그래서 **"배포판(distro) ≈ 유저랜드"** 로 봐도 된다. 배포판을 바꿔도 커널은 그대로.

### 1-4. 구성요소 역할

| 구성요소 | 역할 | 개수 |
|---|---|---|
| 커널 | 하드웨어 관리·자원 분배 | 시스템에 1개 |
| 유저랜드(배포판) | 셸·라이브러리·명령어 모음 | 여러 개 공존 가능 |
| 시스템콜 | 유저랜드 → 커널 요청 창구 | 커널이 제공 |

## 2. 적용 — 컨테이너와 WSL2

### 2-1. 컨테이너가 가벼운 이유 = 커널 공유

```
가상머신(VM):   게스트 OS를 통째로(커널+유저랜드) 부팅  → 무겁다(GB)
컨테이너:       유저랜드만 이미지에 담고, 커널은 호스트 것을 공유  → 가볍다(MB)
```

컨테이너 안 프로세스가 `open()`을 부르면, 그 시스템콜은 **호스트 커널**이 처리한다. 컨테이너는 자기 커널이 없다. 그래서 이미지 안의 "리눅스"는 부팅되는 OS가 아니라 **유저랜드 파일 묶음**이다([[5. 컨테이너 생명주기]]의 "OS를 부팅하는 게 아니다"가 이 얘기).

### 2-2. Windows에서의 전체 그림 (WSL2)

```
Windows (호스트 OS)
   └─ WSL2 = 경량 VM에서 리눅스 커널 1개 실행   ★모두가 공유하는 커널★
         ├─ Ubuntu 배포판          (내가 설치한 유저랜드)
         └─ docker-desktop 배포판   (도커 전용 유저랜드)
               └─ 도커 엔진(dockerd)
                     └─ 컨테이너들   (각자 유저랜드, 커널은 위 커널 공유)
```

- **WSL2**는 리눅스 커널 하나를 돌리는 경량 VM.
- 그 위에 **우분투**와 **docker-desktop** 두 배포판이 얹혀 **같은 커널을 공유**한다. 둘은 형제(둘 다 유저랜드).
- 도커 컨테이너도 그 커널을 공유한다. 그래서 Windows에서 리눅스 컨테이너가 돈다.

---

## 3. 오해 바로잡기

- **도커는 OS가 아니다.** 커널이 아니라 **엔진(프로그램, `dockerd`)**이다. OS 위에서 컨테이너를 부리는 도구.
- **"우분투 OS를 공유"가 아니라 "커널을 공유"다.** 우분투 유저랜드는 컨테이너마다 이미지로 따로 가진다(알파인 컨테이너면 알파인 유저랜드).
- **docker-desktop 배포판 = 유저랜드**다. 우분투와 같은 레벨의 형제이지, 각자가 완전한 OS는 아니다(커널은 공유).

---

## 4. 교훈
- **OS = 커널 + 유저랜드.** 이 분리가 컨테이너·배포판·WSL2를 관통하는 열쇠.
- **커널은 공유, 유저랜드는 각자.** 컨테이너가 VM보다 가벼운 근본 이유.
- **배포판을 바꿔도 커널은 그대로.** 알파인 이미지가 작은 건 유저랜드가 작아서지 커널이 달라서가 아니다.
