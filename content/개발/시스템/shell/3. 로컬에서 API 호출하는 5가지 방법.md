## 개요
> 로컬에서 돌아가는 API(예: `POST http://localhost:4000/api/...`)를 테스트할 때, 상황별로 골라 쓰는 5가지 호출 방법과 선택 기준이다.

아래 예시는 임의의 로컬 API를 대상으로 한다.

- URL: `http://localhost:4000/api/example`
- Method: `POST`
- Body: `{"dryRun": true}` — `dryRun: true`는 "실제 반영 없이 검증만" 이라는 의미이다.

---

## 1. 전체 개념 / 흐름

### 1-1. 큰 그림

같은 API를 호출하는 길이 여러 개다. **어디서 실행하느냐**가 다를 뿐 목적지는 같다.

```
       [로컬 API 서버]  localhost:4000
              ▲
   ┌──────────┼──────────┬───────────┬──────────┐
[브라우저]  [PowerShell] [Postman]  [관리자버튼] [curl]
 콘솔        터미널       GUI        웹 UI       Git Bash
```

### 1-2. 상황별 선택 기준

먼저 결론부터. 지금 뭘 쓸지 이 표로 정한다.

| 상황 | 추천 방식 | 이유 |
|---|---|---|
| 화면이 켜져 있고 즉시 확인 | 브라우저 콘솔 | 가장 빠름, 로그인 세션 그대로 사용 |
| 터미널에서 자동화·반복 | PowerShell / curl | 스크립트화 쉬움 |
| 응답 분석·요청 재사용 | Postman/Insomnia | GUI로 히스토리·환경변수 관리 |
| 운영자가 직접 실행 | 관리자 버튼 | 비개발자도 클릭만으로 |

## 2. 방법별 실행 코드

### 방법 1. 브라우저 개발자도구 콘솔 (가장 빠름)

서비스 페이지가 이미 열려 있으면 즉시 테스트된다.

```javascript
fetch('/api/example', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ dryRun: true }),
})
  .then((r) => r.json())
  .then(console.log)
```

- 상대경로(`/api/...`) 그대로 쓸 수 있고, **현재 로그인 세션·쿠키를 그대로** 사용한다.
- 주의: 브라우저와 API 서버 오리진이 다르면 CORS 영향, 응답이 JSON이 아니면 `r.json()`에서 실패.

### 방법 2. PowerShell (Windows 기본 터미널)

브라우저 없이 독립 실행된다.

```powershell
Invoke-RestMethod `
  -Uri "http://localhost:4000/api/example" `
  -Method POST `
  -ContentType "application/json" `
  -Body '{"dryRun": true}'
```

- 백틱(`` ` ``)은 줄바꿈 연결 문자. Body는 작은따옴표로 감싼 JSON 문자열로 넘긴다.

### 방법 3. Postman / Insomnia (GUI 클라이언트)

요청을 저장·재사용하며 응답을 눈으로 뜯어볼 때 편하다.

- Method: `POST` / URL: `http://localhost:4000/api/example`
- Header: `Content-Type: application/json`
- Body (raw JSON): `{"dryRun": true}`
- 요청 히스토리·환경변수·컬렉션 관리, 상태코드·시간·헤더 확인이 직관적이다.

### 방법 4. 프론트엔드 관리자 버튼

반복 실행이 많고 비개발자도 써야 하면 UI로 만든다.

- 버튼 클릭 → `fetch`로 호출 → 로딩/성공/실패 표시 → 응답 렌더링.
- 사용성은 최고지만 초기 UI 개발 비용이 든다.

### 방법 5. curl (Git Bash·CI)

리눅스·맥·CI와 문법이 같아 파이프라인 연동에 좋다.

```bash
curl -X POST "http://localhost:4000/api/example" \
  -H "Content-Type: application/json" \
  -d '{"dryRun": true}'
```

- 주의: PowerShell 기본 `curl`은 진짜 curl이 아니라 `Invoke-WebRequest` 별칭일 수 있다. Windows에서는 Git Bash/WSL에서 실행하면 혼동이 준다.

## 3. 핵심 통찰

**"지금 화면이 켜져 있나?"** 로 갈리면 쉽다. 켜져 있으면 브라우저 콘솔(방법 1)이 제일 빠르고, 터미널만 있으면 PowerShell(방법 2)이나 curl(방법 5)이다. 나머지는 "재사용·운영자용"이라는 목적이 붙을 때 고른다.

---

## 4. 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| `404 Not Found` | 경로·포트 불일치 | URL, 포트, 라우트 등록 확인 |
| `415 Unsupported Media Type` | Content-Type 누락 | `application/json` 헤더 추가 |
| `400 Bad Request` | JSON Body 형식 오류 | 따옴표·중괄호·키 이름 점검 |
| PowerShell Body 파싱 오류 | 인용·이스케이프 문제 | 작은따옴표 문자열로 JSON 전달 |
| 브라우저 CORS 오류 | 오리진 정책 충돌 | 서버 CORS 설정 또는 동일 오리진 호출 |

> **주의: 실제 반영 실행 전 백업**
> `dryRun: false`(진짜 반영)로 실행하기 전에는 백업·롤백 계획을 세운다. 인증이 필요한 API면 쿠키·토큰 전달 방식을 먼저 확인한다.
