## 개요
> Windows에서 실무로 자주 쓰는 명령을, Linux 대응 명령과 짝지어 정리한 것이다. 로그 감시·포트 확인·일괄 삭제·대량 복사 4가지가 핵심이다.

---

## 1. 전체 개념 / 흐름

### 1-1. 큰 그림

Windows에는 셸이 두 종류다. 용도가 다르다.

```
[PowerShell]  ── 현대 표준. 객체 기반, 기능 강력          ← 실무는 대부분 이쪽
     │            Get-Content / Test-NetConnection / Get-ChildItem
     │
[CMD]         ── 구형. 배치(.bat) 호환용으로만 남음
                  for /r, copy, xcopy
```

### 1-2. 사전 지식 / 용어

- **cmdlet(커맨드릿)** — PowerShell 명령의 단위. `동사-명사` 꼴로 이름이 길다(`Get-Content`, `Test-NetConnection`). 길지만 뜻이 그대로 읽힌다.
- **파이프 `|`** — Linux처럼 앞 결과를 뒤로 넘긴다. 단 PowerShell은 **텍스트가 아니라 객체**를 넘긴다(그래서 `Where-Object`로 속성 필터가 된다).
- **백틱`` ` ``** — PowerShell의 줄바꿈 연결 문자. Linux `\`에 해당.

### 1-3. 비교 예시 — Linux 명령과 짝짓기

익숙한 Linux 명령으로 대응시키면 바로 이해된다. **PowerShell이 길 뿐, 하는 일은 같다.**

| 하는 일 | Linux | Windows(PowerShell) |
|---|---|---|
| 로그 실시간 보기 | `tail -f app.log` | `Get-Content app.log -Wait -Tail 10` |
| 포트 열렸나 확인 | `nc -zv host 1521` | `Test-NetConnection host -Port 1521` |
| 조건으로 파일 찾기 | `find . -name "*.tmp"` | `Get-ChildItem -Recurse -Filter *.tmp` |
| 파일 삭제 | `rm file` | `Remove-Item file` |
| 폴더 통째 복사 | `cp -r src/ dst/` | `robocopy src dst /E` |

## 2. 전체 예시 코드

실무에서 실제로 쓰는 4가지를 그대로 모았다.

```powershell
# 1) 로그 실시간 감시 (tail -f 대응)
Get-Content "C:\logs\error.log" -Wait -Tail 10

# 2) 특정 호스트의 포트가 열려 있는지 확인
Test-NetConnection -ComputerName 10.0.0.5 -Port 1521

# 3) 패턴에 맞는 파일 일괄 삭제 (먼저 -WhatIf로 확인!)
Get-ChildItem -Path "C:\project\web" -Recurse -File |
  Where-Object { $_.Name -match '_[0-9]{6}\.(html|css)$' } |
  Remove-Item -WhatIf

# 4) 폴더 전체를 다른 곳으로 복사 (robocopy = 정석)
robocopy "C:\project\web\src" "C:\project\web\backup" /E /R:2 /W:2
```

## 3. 라인별 / 포인트별 상세 해설

### 3-1. 로그 실시간 감시

```powershell
Get-Content "C:\logs\error.log" -Wait -Tail 10
```

- `-Tail 10` — 마지막 10줄부터 보여줌.
- `-Wait` — 파일에 새 줄이 추가되면 계속 이어서 출력. Linux `tail -f`와 동일. 중단은 `Ctrl+C`.

### 3-2. 포트 연결 확인

```powershell
Test-NetConnection -ComputerName 10.0.0.5 -Port 1521
```

- 결과의 `TcpTestSucceeded : True` 면 포트가 열려 연결된다는 뜻.
- 용도: "DB 서버(예: Oracle 1521 포트)에 방화벽이 막혔나?"를 즉시 진단. 서버·네트워크 문제 1차 확인의 정석이다.

### 3-3. 패턴 일괄 삭제 — 파이프 3단

```powershell
Get-ChildItem -Path "C:\project\web" -Recurse -File |
  Where-Object { $_.Name -match '_[0-9]{6}\.(html|css)$' } |
  Remove-Item -WhatIf
```

- `Get-ChildItem -Recurse -File` — 하위 폴더까지 **파일만** 훑는다.
- `Where-Object { $_.Name -match '...' }` — `$_`는 넘어온 파일 하나. `-match`는 정규식 매칭.
  - `_[0-9]{6}\.(html|css)$` = "밑줄 + 숫자 6자리 + .html 또는 .css로 끝남" → `index_250814.html` 같은 백업 잔여 파일.
- `Remove-Item` — 삭제.

> **용어박스: `-WhatIf`는 안전벨트다**
> `-WhatIf`를 붙이면 실제로 지우지 않고 **"무엇이 지워질지 목록만" 출력**한다.
> 목록을 눈으로 확인한 뒤, 맞으면 `-WhatIf`를 떼고 다시 실행한다. 대량 삭제 전 필수 습관.

### 3-4. robocopy — Windows 대량 복사의 표준

**robocopy = Robust File Copy**("견고한 파일 복사", robo = robust). 로봇이 아니라, 기본 `copy`보다 재시도·로그·미러링까지 되는 강력한 복사라 붙은 이름이다.

```powershell
robocopy "원본폴더" "대상폴더" /E /R:2 /W:2
```

- `/E` (**E**mpty 포함) — 하위 폴더까지 전부(빈 폴더 포함) 복사.
- `/R:2` (**R**etries) — 실패 시 재시도 2회(기본값은 100만 번이라 반드시 지정).
- `/W:2` (**W**ait) — 재시도 간 대기 2초.
- `/MIR` (**MIR**ror) — 원본과 대상을 똑같이 맞춤(대상의 여분 파일은 삭제되니 주의).
- `copy`나 `for /r ... copy` 대신 **robocopy를 쓰는 이유**: 재시도·로그·미러링을 기본 지원해 네트워크 드라이브나 대량 파일에서 안정적이다.

## 4. Windows에서 Unix처럼 쓰기

PowerShell 명령이 길고 불편하면, Windows에서도 Unix처럼 쓰는 길이 있다. 단 셸마다 **"Windows 자체를 얼마나 깊게 제어하느냐"**에 한계가 갈린다.

### 4-1. PowerShell이 왜 긴가

```
[Unix 명령이 짧은 이유]  1970년대 텔레타이프(느린 타이핑) 태생 → ls, cp, rm 극단 축약
        │
[PowerShell이 긴 이유]   2006년 태생, "읽으면 뜻이 보이게" 설계
   → 동사-명사 규칙 강제(Get-Content, Remove-Item): 짧음 대신 일관성·검색성
   → 파일뿐 아니라 레지스트리·서비스·WMI·.NET까지 제어 → 이름이 구체적일 수밖에 없음
```

즉 PowerShell은 파일 셸이 아니라 **Windows 관리 엔진**이다. 긴 건 불편이 아니라 그만큼 깊이 건드리는 대가다.

### 4-2. Unix처럼 쓰는 3가지 길

| 방법 | 설치 | Unix처럼 되는 정도 | Windows 자체 제어 |
|---|---|---|---|
| PowerShell 별칭 | 0 (기본) | `ls` `cd` `cat` `cp` `rm` `pwd` 그대로 먹힘 | — |
| Git Bash | Git 설치 시 딸려옴 | 진짜 bash + coreutils(grep·find·tar) | 약함(userland만) |
| WSL | Windows 기능 | 완전한 Linux(우분투 통째) | 약함(경계 있음) |

- **PowerShell 별칭** — `ls`, `cat`, `cp` 같은 Unix 이름이 PowerShell 명령으로 자동 연결된다. 파일 작업은 이미 Unix처럼 된다. 단 `grep`·`find`는 문법이 다르다.
- **Git Bash** — Git을 깔면 딸려오는 진짜 bash. `grep`·`find`·`curl`이 진짜 coreutils다.
- **WSL(Windows Subsystem for Linux)** — 우분투가 통째로 도는 완전한 Linux. 개발 작업엔 이게 최고다.

### 4-3. 한계 — 그래서 정석은 "둘 다 쓰기"

Git Bash·WSL은 편하지만 **Windows 서비스·레지스트리 같은 OS 자체 제어는 약하다.** 그건 PowerShell만 깊게 된다.

```
[평소 개발·파일 작업]  → Git Bash / WSL (Unix 그대로, 편함)
[Windows 자체 관리]    → PowerShell (포트 진단·서비스 재시작·레지스트리)
```

한쪽을 버리는 게 아니라, 작업 성격에 따라 갈아타는 것이 실무 정석이다.

---

## 5. 핵심 통찰

Windows도 셸은 그냥 **"Linux 명령의 다른 이름표"**로 보면 된다. `Get-Content -Wait` = `tail -f`, `Test-NetConnection` = `nc`. 이름이 길 뿐 개념은 같다. CMD의 `for /r`·`copy`는 배치 호환용 구형이므로, 새로 짤 땐 PowerShell + robocopy로 통일하는 게 정석이다.

---

## 6. 경험과 교훈 / 트러블슈팅

### ❌ 실패: 일괄 삭제가 엉뚱한 파일까지 지움

```powershell
Get-ChildItem -Recurse -File | Where-Object { $_.Name -match '_[0-9]{6}' } | Remove-Item
```

**원인**: 정규식에 `$`(끝 고정)와 확장자 조건이 없어 `report_123456_final.xlsx` 같은 파일까지 걸렸다. 게다가 `-WhatIf` 없이 바로 실행했다.

**해결**: ① 정규식을 `_[0-9]{6}\.(html|css)$`처럼 끝까지 고정하고, ② 반드시 `-WhatIf`로 목록을 먼저 확인한 뒤 삭제한다.

---

## 7. Best Practices
- 삭제·이동 cmdlet은 무조건 `-WhatIf`로 먼저 예행 연습한다.
- 대량 복사는 `copy`가 아니라 `robocopy`를 쓴다.
- 새 스크립트는 CMD(.bat)가 아니라 PowerShell(.ps1)로 작성한다.
