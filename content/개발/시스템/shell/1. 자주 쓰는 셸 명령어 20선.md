## 개요
> Linux·Unix·Git Bash에서 매일 쓰는 핵심 명령어 20개를, 실무 빈도(★등급)와 발등 찍는 함정 위주로 정리한 것이다.

---

## 1. 전체 개념 / 흐름

### 1-1. 큰 그림

명령어는 하는 일에 따라 4묶음으로 나뉜다. 이 순서대로 손이 간다.

```
[이동·탐색]  cd → ls → pwd → find → grep
     │
     ▼
[파일 조작]  cp → mv → rm → mkdir
     │
     ▼
[내용 확인]  cat → less → head → tail
     │
     ▼
[프로세스·기타]  ps → kill → top → curl → wget → tar → chmod
```

### 1-2. 사전 지식 / 용어

- **플래그(옵션)** — 명령어 뒤에 `-` 로 붙여 동작을 바꾸는 스위치. 예: `ls -a` 의 `-a`.
- **상대경로 / 절대경로** — `./file`(현재 위치 기준) vs `/home/user/file`(루트 기준).
- **와일드카드 `*`** — "아무 문자열". `*.js` = 확장자가 js인 모든 파일.
- **파이프 `|`** — 앞 명령어의 출력을 뒤 명령어의 입력으로 넘김. 예: `ps aux | grep node`.

### 1-3. 실무 빈도로 본 우선순위

20개를 다 똑같이 외울 필요는 없다. 실제로 손이 가는 빈도로 나누면 아래와 같다.

| 등급 | 명령어 | 언제 |
|---|---|---|
| ★★★ 매일 | `cd` `ls` `grep` `cat` `tail` `rm` `cp` `mv` `mkdir` | 기본 이동·확인·수정 |
| ★★ 자주 | `find` `ps` `kill` `curl` `chmod` `head` `less` | 검색·프로세스·권한·요청 |
| ★ 가끔 | `pwd` `top` `wget` `tar` | 알아두면 유용 |

### 1-4. 구성요소 역할 (풀네임 포함)

풀네임(영어 원형)을 알면 암기가 아니라 이해가 된다. **굵은 글자**가 약자로 남은 부분이다.

| 명령어 | 하는 일 | 대표 예시 | 풀네임 (영어 원형) |
|---|---|---|---|
| `ls` | 파일/폴더 목록 나열 | `ls -alh` | **l**i**s**t |
| `cd` | 디렉터리 이동 | `cd ..` / `cd -` | **c**hange **d**irectory |
| `pwd` | 현재 경로 출력 | `pwd` | **p**rint **w**orking **d**irectory |
| `cp` | 복사 | `cp -r src/ dist/` | **c**o**p**y |
| `mv` | 이동·이름변경 | `mv old.txt new.txt` | **m**o**v**e |
| `rm` | 삭제 | `rm -rf node_modules/` | **r**e**m**ove |
| `mkdir` | 폴더 생성 | `mkdir -p a/b/c` | **m**a**k**e **dir**ectory |
| `find` | 파일 검색 | `find . -name "*.js"` | find (그대로) |
| `grep` | 문자열 검색 | `grep -R "error" .` | **g**lobal **r**egular **e**xpression **p**rint |
| `cat` | 내용 전체 출력 | `cat file.txt` | con**cat**enate (이어붙이기) |
| `less` | 페이지 단위 보기 | `less bigfile.log` | less ("less is more" 말장난) |
| `tail` | 끝부분 보기 | `tail -f app.log` | tail (꼬리 = 끝부분) |
| `head` | 앞부분 보기 | `head -n 20 data.txt` | head (머리 = 앞부분) |
| `ps` | 프로세스 목록 | `ps aux \| grep node` | **p**rocess **s**tatus |
| `kill` | 프로세스 종료 | `kill -9 1234` | kill (시그널 전송) |
| `top` | 실시간 모니터 | `top` | **t**able **o**f **p**rocesses |
| `curl` | HTTP 요청 | `curl https://api.example.com` | **c**lient **URL** |
| `wget` | 파일 다운로드 | `wget https://.../file.zip` | **w**eb **get** |
| `tar` | 압축/해제 | `tar -czvf a.tar.gz dir/` | **t**ape **ar**chive |
| `chmod` | 권한 변경 | `chmod 755 script.sh` | **ch**ange **mod**e |

**어원이 재밌어서 안 잊는 것들**
- `grep` — 옛 편집기(ed)의 명령 `g/re/p`(global / regular expression / print)가 그대로 이름이 됐다.
- `tar` — 옛날 백업용 **테이프**(tape archive)에서 온 이름. 지금은 테이프를 안 쓰는데 이름만 남았다.
- `less` — 기존 페이저 `more`의 개선판이라 반댓말로 지은 말장난이다("less is more").
- `cat` — 원래 "여러 파일을 이어붙이는(concatenate)" 명령이다. 한 파일만 주면 그게 그냥 화면 출력으로 보이는 것이다.

## 2. 전체 예시 코드

하루 작업을 한 흐름으로 이으면 이렇게 된다.

```bash
cd /var/www/project          # 프로젝트로 이동
ls -alh                      # 숨김 파일 포함, 크기 사람이 읽기 좋게
grep -R "TODO" ./src         # src 아래에서 TODO 전부 검색
tail -f logs/app.log         # 로그 실시간 감시 (Ctrl+C로 중단)
ps aux | grep node           # node 프로세스 찾기
kill -9 1234                 # 해당 PID 강제 종료
```

## 3. 라인별 / 포인트별 상세 해설

표만 외우면 금방 까먹는다. 실무에서 **발등 찍는 플래그·함정**만 골라 정리한다.

### 3-1. 옵션 풀네임 사전

옵션도 풀네임을 알면 안 까먹는다. 특히 **같은 `-f`가 명령마다 뜻이 다른** 함정을 조심한다.

| 옵션 | 풀네임 | 뜻 |
|---|---|---|
| `-a` | **a**ll | 숨김 파일까지 전부 |
| `-l` | **l**ong | 상세(긴) 목록 |
| `-h` | **h**uman-readable | 크기를 KB/MB 단위로 |
| `-r`, `-R` | **r**ecursive | 하위 폴더까지 재귀적으로 |
| `-v` | **v**erbose | 과정을 자세히 출력 |
| `-p` | **p**arents | 없는 부모 폴더까지 생성 (mkdir) |
| `-n` | **n**umber | 줄 수 지정 (head/tail) |
| `-i` | **i**nteractive | 하나씩 확인하며 실행 (rm) |
| tar `-c -x -z -f` | **c**reate / e**x**tract / g**z**ip / **f**ile | 압축 / 해제 / gzip / 파일명 |
| curl `-d -H -X` | **d**ata / **H**eader / --request 단축 | 본문 / 헤더 / HTTP 메서드 |
| `-f` (주의) | force · follow · file | **명령마다 다름**: `rm -f`=강제, `tail -f`=따라가기, `tar -f`=파일명 |

### 3-2. 자주 까먹는 플래그

- `ls -alh` — `-a`(숨김 파일까지), `-l`(상세 목록), `-h`(크기를 KB/MB로). 셋을 붙여 쓴다.
- `cd -` — 바로 직전에 있던 경로로 되돌아감. 두 폴더를 오갈 때 편하다.
- `cp -r` — 폴더를 통째로 복사할 땐 `-r`(recursive)가 없으면 실패한다.
- `mkdir -p a/b/c` — `-p`가 있으면 중간 폴더(a, a/b)가 없어도 한 번에 다 만든다.
- `grep -R "error" .` — `-R`(대문자, recursive)는 하위 폴더 전체를 훑는다. `.`은 현재 폴더.
- `find . -name "*.js"` — `-name` 뒤 패턴은 반드시 따옴표로 감싼다(안 그러면 셸이 `*`를 먼저 풀어버림).

### 3-3. tar — 글자 조합이 헷갈리는 대표주자

```bash
tar -czvf archive.tar.gz folder/   # 압축(만들기)
tar -xzvf archive.tar.gz           # 해제(풀기)
```

- `c` = **c**reate(압축 생성), `x` = e**x**tract(해제) — 이 한 글자가 방향을 바꾼다.
- `z` = gzip 압축, `v` = 과정 출력(verbose), `f` = 파일 이름 지정.
- 외우는 법: **"압축은 cf, 해제는 xf, 가운데 zv는 그대로"**.

### 3-4. curl — POST 요청 기본형

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -d '{"a":1}' \
  https://api.example.com
```

- `-X POST` — HTTP 메서드 지정(기본은 GET).
- `-H` — 헤더 추가. `-d` — 본문(body) 데이터.

### 3-5. chmod — 숫자 권한의 뜻

```bash
chmod 755 script.sh
```

> **용어박스: 755가 뭔가**
> 3자리는 각각 `소유자 / 그룹 / 그 외` 권한이다. 숫자 = 읽기(4) + 쓰기(2) + 실행(1)의 합.
> `7` = 4+2+1(전부), `5` = 4+1(읽기+실행). 즉 755 = "주인은 다 되고, 나머지는 읽고 실행만".
> `chmod +x script.sh` 는 "실행 권한만 켜라"는 간편형이다.

## 4. 핵심 통찰

명령어 20개 암기가 목적이 아니다. **★★★ 9개를 손에 붙이고, 나머지는 "이런 게 있었지"만 기억해 필요할 때 `--help`로 확인**하면 된다. 진짜 실력은 명령어 개수가 아니라 플래그와 함정을 아는 데서 나온다.

## 5. 경험과 교훈 / 트러블슈팅

### ❌ 위험: `rm -rf`

```bash
rm -rf node_modules/     # 정상: 특정 폴더 삭제
rm -rf /                 # 절대 금지: 루트부터 전부 삭제
```

**원인**: `rm -rf`는 확인 없이 즉시 삭제한다. 경로에 공백·오타가 있으면 의도치 않은 곳이 날아간다.

**해결**: 경로를 지운 뒤 반드시 눈으로 다시 읽는다. 애매하면 `-rf` 대신 `rm -ri`(하나씩 확인)로 먼저 돌려본다.

---

## 6. Best Practices
- 명령어가 기억 안 나면 `명령어 --help` 또는 `man 명령어`로 즉시 확인한다.
- 삭제·이동 전에는 경로를 `ls`로 한 번 확인하는 습관을 들인다.
- 긴 로그는 `cat`으로 통째로 쏟지 말고 `less`/`tail`로 잘라 본다.
