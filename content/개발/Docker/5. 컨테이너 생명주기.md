# 개요
> "컨테이너를 띄웠는데 왜 바로 꺼지지?" 답은 **PID 1**에 있다. 컨테이너는 메인 프로세스(PID 1)가 살아 있는 동안만 산다. 개념 배경은 [[2. Docker 핵심 개념]], `CMD`는 [[3. Dockerfile]].

---

## 1. 전체 개념 / 흐름

### 1-1. 큰 그림 — 컨테이너의 수명 = PID 1의 수명

도커의 철칙: **컨테이너는 메인 프로세스(PID 1)가 종료되는 순간 함께 종료된다.**

여기서 핵심은, 컨테이너는 VM처럼 **OS를 부팅하는 게 아니라는** 점이다. 커널은 호스트와 공유하고, 이미지 안의 리눅스는 "실행 중인 OS"가 아니라 파일 묶음일 뿐이다. 실제로 실행되는 건 **`CMD` 프로세스 하나**라, 그게 끝나면 컨테이너는 할 일이 없어 종료된다. (프로세스 없이 "OS만 깔고 대기"하는 상태는 컨테이너에 없다.)

```
docker run
   │
   ▼
[PID 1: CMD에 지정한 명령 실행]
   │
   ├─ PID 1이 계속 살아 있음  → 컨테이너 유지
   │
   └─ PID 1이 종료됨          → 컨테이너 즉시 종료
```

즉 컨테이너 안에서 프로세스를 아무리 여럿 띄워도, **PID 1 하나가 끝나면 전부 같이 죽는다.**

### 1-2. 사전 지식 / 용어

- **PID 1** — 컨테이너 안에서 **가장 먼저 뜨는 프로세스**. `CMD`(또는 `ENTRYPOINT`)에 지정한 명령이 여기에 온다. 리눅스에서 PID 1은 특별한 "우두머리" 프로세스.
- **포어그라운드(foreground)** — 실행한 자리에서 **떠나지 않고 계속 붙어 있는** 실행 방식. 터미널을 점유한다.
- **백그라운드/데몬(daemon)** — 실행하자마자 **뒤로 빠지고 자기 자신은 종료**되는 방식. 서버 프로그램이 흔히 이렇게 동작.

### 1-3. 비교 — `pm2 start` vs `pm2-runtime`

Node.js 프로세스 매니저 **PM2**로 보면 원리가 선명하다. 같은 앱을 띄우는데 결과가 정반대.

| 항목 | `pm2 start` (컨테이너에서, 잘못) | `pm2-runtime` (도커 전용, 권장) |
|---|---|---|
| 실행 방식 | 자식 프로세스 fork 후 **자신은 데몬으로 빠지며 종료** | 자식 관리하며 **자신이 포어그라운드로 계속 삶** |
| PID 1 | 사라짐 | 유지됨 |
| 컨테이너 | 즉시 종료 | 유지 |

```
CMD: pm2 start app.js
   │
   ▼
PM2가 앱을 자식으로 fork → PM2 자신(PID 1)은 데몬 모드로 전환하며 종료
   │
   ▼
PID 1 없음 → 컨테이너 즉시 종료

CMD: pm2-runtime app.js
   │
   ▼
PM2가 자식을 관리하면서 자신(PID 1)은 포어그라운드에 계속 살아 있음
   │
   ▼
컨테이너 유지
```

### 1-4. 다른 서버들도 같은 원리

| 프로그램 | 포어그라운드용 실행 |
|---|---|
| Apache | `apache2-foreground` (일반 `apachectl start`는 데몬화 → 죽음) |
| Nginx | `nginx -g "daemon off;"` |
| PM2 | `pm2-runtime` |

공통점: **"데몬으로 빠지지 말고 앞에 붙어 있어라"** 옵션을 준다.

이 "포어그라운드로 띄워라"는 **도커 전용 요구**다. 도커 없는 일반 서버(물리·VM)에선 `systemd` 같은 관리자가 프로세스를 돌보므로 오히려 데몬화(백그라운드)가 정상이다. 도커엔 그 관리자가 없고 컨테이너 수명이 PID 1 하나에 걸려 있어 포어그라운드가 필요하다.

## 2. 전체 예시 코드

```dockerfile title="Dockerfile"
FROM php:8.1-apache
# apache2-foreground: Apache를 포어그라운드로 → PID 1 유지 → 컨테이너 유지
CMD ["apache2-foreground"]
```

```dockerfile title="Node.js 예"
FROM node:20
WORKDIR /app
COPY . .
RUN npm install
# (잘못) CMD ["pm2", "start", "app.js"]  → 데몬화되어 컨테이너 죽음
# (권장) pm2-runtime: 포어그라운드 유지
CMD ["pm2-runtime", "app.js"]
```

---

## 3. 라인별 해설

- `CMD ["apache2-foreground"]` — Apache의 포어그라운드 실행 명령. 이게 PID 1이 되어 살아 있으므로 컨테이너가 유지된다.
- `CMD ["pm2-runtime", "app.js"]` — `pm2 start`가 아니라 `pm2-runtime`. 도커 안에서 PM2를 쓸 땐 이 명령이 정답.
- **왜 배열 형식(`["...", "..."]`)인가** — exec 형식. 쉘을 거치지 않고 명령을 직접 PID 1로 실행해 신호(예: `docker stop`의 SIGTERM)가 프로세스에 정확히 전달된다.

---

## 4. 경험과 교훈 / 트러블슈팅

### 실패: 컨테이너가 뜨자마자 `Exited (0)`

```bash
docker ps -a
# STATUS: Exited (0) 3 seconds ago
```

**원인**: `CMD`가 데몬화되는 명령(`pm2 start`, `apachectl start` 등)이라 PID 1이 곧바로 종료 → 컨테이너 종료.

**해결**: 포어그라운드 명령으로 교체.
```dockerfile
CMD ["pm2-runtime", "app.js"]   # pm2 start → pm2-runtime
```

---

## 5. 교훈
- **컨테이너의 `CMD`는 "떠나지 않는(포어그라운드) 프로세스"여야 한다.** 데몬화되는 명령을 쓰면 PID 1이 사라져 컨테이너가 죽는다.
- **"컨테이너가 바로 꺼진다" → 십중팔구 PID 1 문제.** `docker ps -a`의 `Exited (0)`가 신호. `docker logs`로 확인.
- **서버마다 포어그라운드 옵션이 따로 있다.** Apache `apache2-foreground`, Nginx `daemon off;`, PM2 `pm2-runtime`.
- **한 컨테이너 = 한 주 프로세스(PID 1)가 원칙.** 여러 서버를 한 컨테이너에 욱여넣지 말고, 서비스별로 컨테이너를 나눈다([[4. Docker Compose]]).
