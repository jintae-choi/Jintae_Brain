## 개요
> 이미 파일이 들어 있는 폴더(예: `~/.claude`)에는 `git clone`이 안 된다. `init → remote add → fetch → checkout` 네 단계로 기존 원격 저장소를 붙이는 방법과, `-f`/`-t` 옵션, `.git`(저장소 본체) vs 작업폴더 개념을 정리한다.

---

## 1. 문제: 왜 `git clone`이 안 되나

`git clone`은 **대상 폴더가 없거나 비어 있어야** 동작한다. 이미 파일이 든 폴더에 대고 clone하면 이렇게 거부된다.

```
fatal: destination path '.' already exists and is not an empty directory.
```

> [!EXAMPLE] 실제로 마주치는 상황
> `~/.claude`(Claude Code 설정 폴더)를 개인 지침 저장소로 관리하려는 경우. 이 폴더엔 이미 `.credentials.json`·`sessions/`·`settings.json` 등이 들어 있어 clone이 막힌다.

---

## 2. 해결: init → remote add → fetch → checkout

폴더 **안에서** git을 초기화한 뒤 원격을 붙여 꺼내는 방식이다.

```bash
cd ~/.claude
git init -b main                                        # ① 이 폴더를 git 저장소로 초기화 (기본 브랜치 main)
git remote add origin https://github.com/user/repo.git  # ② 원격을 origin 별명으로 등록
git fetch origin                                        # ③ 원격 커밋·파일을 .git 안으로만 내려받음
git checkout -f -t origin/main                          # ④ 추적 파일을 작업폴더로 꺼냄 + 추적 설정
```

| 단계 | 명령 | 하는 일 |
|---|---|---|
| ① | `git init -b main` | 기존 파일은 그대로 둔 채 이 폴더를 git이 관리하도록 시작. `-b main` = 기본 브랜치 이름 |
| ② | `git remote add origin …` | 원격 저장소를 `origin`이라는 별명으로 연결 |
| ③ | `git fetch origin` | 원격의 커밋·파일을 `.git`에만 내려받음 — 작업폴더엔 **아직 안 보인다** |
| ④ | `git checkout -f -t origin/main` | 추적 파일을 실제 작업폴더로 꺼내고, 로컬 `main`이 `origin/main`을 추적하게 설정 |

> [!NOTE] clone도 사실 같은 일을 한다
> `git clone`은 위 ①~④(+작업폴더 펼치기)를 **한 번에** 해주는 단축 명령이다. 폴더가 비어 있을 때만 쓸 수 있을 뿐, 내부 동작은 다르지 않다.

---

## 3. `.git` 폴더 vs 작업폴더 (금고 vs 책상)

git 저장소는 두 층으로 나뉜다.

| | 정체 | 내용 |
|---|---|---|
| **`.git/` 폴더** | 저장소 본체 (금고) | 모든 커밋·모든 버전·브랜치 이력 전부가 압축돼 보관됨 |
| **작업폴더의 파일들** | 작업 책상 (working tree) | `.git` 금고에서 특정 버전(보통 최신)을 꺼내 펼친 실제 사본. 편집기에서 보이는 것 |

```
[원격 저장소]
   ↑ push            ↓ fetch     (원격 → 로컬 .git)
[로컬 .git = 금고]
   ↑ commit          ↓ checkout  (.git → 작업폴더)
[작업폴더 = 책상 (눈에 보이는 파일)]
```

- **`fetch`는 금고(.git)만 채운다.** 그래서 fetch만 하면 파일이 눈에 안 보인다.
- **`checkout`이 금고에서 책상으로 꺼낸다.** 이때부터 파일이 나타난다.
- 작업폴더 파일을 실수로 지워도 `.git`에 남아 있으면 `git checkout`으로 복구된다. 반대로 `.git`을 지우면 이력이 사라져 평범한 폴더가 된다.

> commit / push / pull의 자세한 흐름은 [[1. git 원격 동기화 파이프라인]] 참고.

## 4. `-f` / `-t` 옵션

### `-f` (`--force`)
체크아웃할 때 작업폴더에 **같은 이름 파일이 이미 있으면 원격 버전으로 덮어쓴다.**

- force는 **git이 추적하는 파일만** 건드린다. 추적 안 하는 로컬 파일(`.credentials.json` 등)은 손대지 않는다.
- 단, 이미 `README.md`·`.gitignore` 같은 **동명 파일**이 있으면 원격 것으로 덮어쓰므로, 필요하면 미리 백업한다.

### `-t` (`--track`)
로컬 `main` 브랜치가 `origin/main`을 **추적(track)**하게 만든다.

- 이후 `git pull`·`git push`를 브랜치 이름 없이 쓸 수 있다.
- `git push -u origin <브랜치>`의 `-u`와 같은 "추적 연결"을 checkout 시점에 해주는 것. ([[0. git 기본 명령어]]의 `push -u` 참고)

---

## 5. 안전 포인트

> [!TIP] 화이트리스트 `.gitignore`와 함께 쓰면 안전하다
> `~/.claude`처럼 민감/방대한 파일이 섞인 폴더를 저장소로 쓸 땐, `.gitignore`를 **전부 제외 후 필요한 것만 허용**하는 화이트리스트로 짠다.
> ```
> *
> !.gitignore
> !README.md
> !지침파일.md
> ```
> 이러면 `-f` 체크아웃이 실수로 자격증명·세션 기록을 커밋하거나 덮어쓸 일이 없다.
