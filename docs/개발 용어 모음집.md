## 2. 협업·배포

### GitHub Actions
- GitHub가 제공하는 CI/CD 자동화 플랫폼.
- 저장소의 이벤트(푸시·PR·릴리스 등)에 반응해 워크플로우(`.github/workflows/*.yml`)를 실행.
- 이 프로젝트도 `.github/workflows/deploy.yml`로 GitHub Pages 배포 자동화.

### CI/CD
- **Continuous Integration / Continuous Deployment**. 지속적 통합 및 지속적 배포.
- 소스 코드 변경분을 주기적으로 병합(CI)하고, 통과한 산출물을 자동으로 서비스에 반영(CD)하는 실천법.
- 목적: 수동 배포의 사람 실수 제거, 빠른 피드백 루프.

### 풀 리퀘스트 (Pull Request)
- 작업 브랜치의 변경을 다른 브랜치(보통 `main`·`dev`)로 **병합 요청**하는 행위.
- 리뷰·토론·CI 체크가 붙는 협업 단위. 코드 변경 + 맥락(설명·스크린샷·테스트)을 묶어 공유.
- 줄여서 **PR**이라 부름.

### 파이프라인
- 입력을 여러 단계로 흘려 보내며 가공·전달하는 연속 처리 구조.
- 개발 영역에서 자주 등장하는 두 종류를 구분할 것.

| 구분 | CI/CD 파이프라인 | 데이터 파이프라인 |
| --- | --- | --- |
| 목적 | 소프트웨어의 안정적 자동 배포 | 데이터의 수집·가공·저장 |
| 주요 대상 | 소스 코드 (JS, PHP 등) | 원시 데이터 (DB·로그 등) |
| 핵심 단계 | 빌드 → 테스트 → 배포 | 추출(Extract) → 변환(Transform) → 적재(Load) |
| 예시 | 원격 저장소 푸시 → Vercel 자동 반영 | MySQL 추출 → 통계 DB로 변환·적재 |

## 3. 문제 해결

### 트러블슈팅 (Troubleshooting)
- 시스템에서 발생한 문제의 **원인을 규명하고 해결하는 체계적 과정**.
- 어원: 초기 기계에서 소음(Trouble)이 나는 부위를 때려(Shooting) 고치던 것에서 유래.
- 핵심은 '고치는 것'이 아니라 '어디가 왜 고장 났는지 찾는 조사 과정'.

**디버깅과의 비교**

| 항목 | 트러블슈팅 | 디버깅 |
| --- | --- | --- |
| 범위 | HW·네트워크·인프라 등 시스템 전체 | 주로 SW 소스 코드 내부 |
| 대상 | 배포·운영 중 시스템 장애 | 개발 단계의 논리적 오류(Bug) |
| 목적 | 가동 중단 최소화·정상 복구 | 코드 결함 제거·의도한 동작 구현 |
| 주체 | 인프라 엔지니어·DBA·시스템 관리자 | 소프트웨어 개발자 |

**표준 프로세스**
1. **현상 파악**: 에러 로그 확인, 사용자 제보 분석.
2. **재현**: 동일 문제가 발생하는 최소 조건 확립.
3. **가설 수립**: 로그·모니터링 기반 원인 추정 (예: DB 커넥션 풀 부족, 네트워크 지연).
4. **검증**: 가설에 따라 설정·코드 수정 적용.
5. **해결·기록**: 정상 작동 확인 후 유사 장애 방지를 위해 기술 블로그·위키에 기록.

**관련 용어**
- **DBA (Database Administrator)**: 데이터베이스 관리자. DB 시스템의 운영을 책임지는 전문가.
- **Connection Pool**: DB 커넥션을 미리 만들어 두고 재사용하는 보관소. 자원 효율성↑.

## 4. 라이브러리·프레임워크

### Prisma
- Node.js·TypeScript용 **ORM (Object-Relational Mapper)**.
- SQL을 직접 쓰는 대신 **TypeScript 코드로 DB를 다루게 해주는 도구**.
- 스키마(`schema.prisma`) 기반으로 타입 안전한 쿼리 클라이언트를 생성.

### React
- 한 줄 요약: **HTML을 JS로 찍어내는 도구**.
- Meta가 만든 UI 라이브러리. 컴포넌트 단위로 UI를 조립하고, 상태(state) 변화에 따라 자동으로 화면을 다시 그림.
- JSX 문법으로 JS 안에 HTML-유사 구문을 섞어 쓰는 것이 특징.
