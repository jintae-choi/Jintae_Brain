# Jintae Brain — AI 운영 가이드

> Claude Code 자동화 자산(스킬·서브에이전트·훅)을 이 프로젝트에 맞춰 세팅한 내용과 **설계 이유**를 정리한다. 기준일 2026-09-17.
> 지침 원본은 [AGENTS.md](../../AGENTS.md)(도구 중립), 클로드 전용 규칙은 [CLAUDE.md](../../CLAUDE.md). 이 문서는 사용법과 "왜 이렇게 구성했나"만 담는다.

---

## 1. 전체 흐름

```
사용자 요청
    │
    ├─ 새 노트 골격만      ──► /new-note        ──► 템플릿 frontmatter 치환·번호·index 등록
    ├─ 노트 한 번에 완성   ──► /compose-note    ──► 뼈대 → 내용 → 문체 → 용어 보강
    ├─ 기존 노트 재구성    ──► /polish-note     ──► 표준 흐름 재배치·간결체
    ├─ 용어 해설 보강      ──► /add-terms       ──► 코드블록 용어 중 누락분만 bullet
    ├─ 노트 1개 품질 검사  ──► /review-note     ──► note-reviewer 서브에이전트 리포트
    ├─ 연결 문서 제안      ──► note-linker 에이전트 ─► [[wikilink]] 후보
    ├─ 프로젝트 전체 감사  ──► /audit-project   ──► env·docs·content 감사 에이전트 3개 병렬
    └─ 커밋 메시지·커밋    ──► /commit-note     ──► 이 repo 관례 접두어로 초안 → 승인 → 로컬 커밋

세션 시작마다   SessionStart 훅 session-start.sh ──► git 상태 + 로컬웹(8080) 실행 여부 주입
Write/Edit 마다 PostToolUse 훅 validate-md.sh   ──► content/*.md frontmatter·문체·H1 검사 → 경고를 모델에게 보임
```

### 설계 원칙
1. **노트 구조는 템플릿이 단일 원본** — [content/templates/기본 문서 템플릿.md](../../content/templates/%EA%B8%B0%EB%B3%B8%20%EB%AC%B8%EC%84%9C%20%ED%85%9C%ED%94%8C%EB%A6%BF.md). 스킬·에이전트는 흐름을 재기술하지 않고 템플릿을 가리킨다. 레퍼런스 구현: [content/개발/git/6. git-hooks.md](../../content/%EA%B0%9C%EB%B0%9C/git/6.%20git-hooks.md).
2. **자주 하는 작업은 스킬, 컨텍스트 분리가 필요한 작업은 서브에이전트, 매번 자동 체크는 훅.**
3. **모든 자동화는 읽기 우선.** 파일 수정이 필요한 작업은 사용자 승인 후 실행.
4. **커맨드(`.claude/commands/`)는 쓰지 않는다.** 공식 문서(code.claude.com/docs/en/skills, 2026-09) 원문: "Custom commands have been merged into skills… Prefer a skill for new work." 같은 이름이 둘 다 있으면 스킬이 이기고, 스킬만 보조 파일 폴더·`name`·`paths`를 지원한다. 2026-09-17에 커맨드 6개를 전부 스킬로 옮겼다.

## 3. 스킬 7개

| 스킬 | 언제 | 인자 | 모델 자동 호출 | 하는 일 |
|---|---|---|---|---|
| `/new-note` | 새 주제 노트를 시작할 때 | `<카테고리> <제목>` | 가능 | 템플릿 골격만 생성, 번호·index 등록. 내용은 채우지 않음 |
| `/compose-note` | 대화·붙여넣은 텍스트로 노트를 한 번에 완성할 때 | `<카테고리> <제목>` | 가능 | new-note → 내용 채움 → polish 로직 → add-terms. 공개 검열 포함 |
| `/polish-note` | 옛 노트가 표준 흐름과 어긋날 때 | `<경로>` | 가능 | 진단 → 승인 → 재배치·간결체. 지식 삭제 금지 |
| `/add-terms` | 코드블록은 많은데 해설이 빠졌을 때 | `<경로>` | 가능 | 누락 용어만 제시 → confirm 항목만 반영 |
| `/review-note` | 노트 1개 품질 점검 | `<경로>` (생략 시 수정 중 파일) | 가능 | note-reviewer 위임, 우선순위 3개 요약 |
| `/audit-project` | 프로젝트 전체 점검 | `[env\|docs\|content]` | **불가** | 감사 에이전트 3개 병렬 위임, Top 3 |
| `/commit-note` | 로컬 커밋 | `[힌트]` | **불가** | 접두어 규약(`공부노트 추가:`·`정리:`·`설정:`·`feat(영역):`)으로 초안 → 승인 → 커밋. 푸시 없음(원격까지는 전역 `/sync`) |

사용 예:
```
/compose-note 개발/서버/배포 GitHub Pages 배포 구조
/review-note content/개발/git/6. git-hooks.md
/audit-project env
```

## 4. 서브에이전트 5개

| 에이전트 | 입력 | 출력 | 왜 분리했나 |
|---|---|---|---|
| `note-reviewer` | 노트 1개 | PASS/FAIL 체크리스트(frontmatter·표준 흐름·문체·wikilink·코드블록 해설) | Grep·Read 결과가 메인 대화에 쌓이지 않게 |
| `note-linker` | 노트 1개 | 삽입 권장 `[[wikilink]]` 후보 + 새 노트 후보 | content 전체 스캔을 격리 |
| `env-auditor` | 없음 | `.claude/`·루트 설정 7축 체크리스트 | `/audit-project env` |
| `docs-auditor` | 없음 | README·AGENTS·docs/ 문서별 평가 | `/audit-project docs` |
| `content-auditor` | 없음 | 문제 노트 분류 A~F + TOP-5 | `/audit-project content` |

호출 예: `note-linker 에이전트로 content/개발/git/6. git-hooks.md 의 링크 후보 찾아줘`.

## 5. 훅 2개

### `SessionStart` → `session-start.sh`
- **언제**: 세션 시작(`startup`·`resume`).
- **동작**: git 브랜치·변경 파일·최근 커밋 3개 + 로컬웹(8080) 실행 여부를 stdout 으로 출력 → SessionStart 는 stdout 이 모델 초기 컨텍스트에 들어간다.

### `PostToolUse: Write|Edit` → `validate-md.sh`
- **대상**: `content/` 하위 `.md` (`templates/` 제외).
- **검사**: frontmatter 블록·`title`·`tags`·`date` / 서술형 종결 3회 이상 / `## 개요` 존재 / 본문 H1. **`index.md` 는 `## 개요`·H1 검사 제외**(폴더 랜딩 페이지 관례).
- **출력 방식 — exit 2**: 공식 문서 hooks.md 원문 "Stderr from a hook that exits 0 goes to the debug log only… Claude never sees it. On PostToolUse, exit 2 instead so Claude sees the stderr even though the tool already ran." 2026-09-17 실측에서도 exit 0 이던 경고는 모델에 한 번도 도달하지 않았다. 그래서 경고가 있으면 exit 2 로 끝낸다 — 도구는 이미 실행됐으므로 차단이 아니라 "경고를 읽고 고쳐라"가 된다.
- **수동 테스트**:
  ```bash
  # 경고가 나야 하는 경우(frontmatter 없는 임시 파일) → exit 2
  printf '# x\n' > content/_t.md; printf '{"tool_input":{"file_path":"content/_t.md"}}' | bash .claude/hooks/validate-md.sh; echo "exit=$?"; rm content/_t.md
  # index.md 는 H1·개요 예외 → exit 0, 출력 없음
  printf '{"tool_input":{"file_path":"content/개발/git/index.md"}}' | bash .claude/hooks/validate-md.sh; echo "exit=$?"
  ```

### 없앤 훅 (2026-09-17)
- `check-engine-mount.sh`(PreToolUse)·`session-end.sh`(SessionEnd): Docker dev 모드 전제였다. 로컬웹 `quartz build --serve` 가 `quartz/` 안 `.ts`/`.tsx`/`.scss` 를 이미 감시해(`quartz/cli/handlers.js` watch 목록) 모드 전환이 필요 없고, exit 0 stderr 라 모델이 보지도 못했다.

## 7. 설정 관리 원칙

- **중복 금지**: `AGENTS.md`가 단일 원본. `CLAUDE.md`는 `@AGENTS.md` 임포트 + 클로드 전용 규칙(토큰 절약·편집 안전)만. 전역 지침을 프로젝트에서 다시 임포트하지 않는다(이중 로드).
- **`.claude/` 커밋**: 스킬·에이전트·훅은 git에 포함 — 어느 컴퓨터든 clone 만으로 같은 환경. 단 `settings.json` 에 권한 기본값(`bypassPermissions` 등)을 넣지 않는다 — 공개 repo 라 clone 하는 남에게도 적용된다. 권한은 전역 설정 몫.
- **훅 규칙**: 모델이 반응해야 하는 경고는 PostToolUse 에서 exit 2. exit 0 + stderr 는 아무에게도 안 보인다.
- **템플릿 고정**: 템플릿이 표준 흐름의 단일 원본. 변경 시 이 문서·`AGENTS.md` 콘텐츠 규칙도 갱신.
- **문서 동기화**: `.claude/`·`AGENTS.md`·`CLAUDE.md` 를 바꾸면 이 문서와 `README.md` 링크를 같은 맥락에서 바로 갱신한다.
